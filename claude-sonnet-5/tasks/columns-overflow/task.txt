Fix an arithmetic overflow in textwrap's `wrap_columns`. The function documents that it panics only when the number of columns is zero, but computing the combined width of the middle gaps multiplies the gap width by `columns - 1`, so a very large number of columns overflows a `usize` and panics in debug builds with "attempt to multiply with overflow". Compute the inner width available to the columns so that this product saturates instead of overflowing; nothing is lost because such a product exceeds the total width and the remaining width is zero either way. Preserve the existing wrapping results for ordinary inputs, the documented panic on zero columns, and the public API. Add regression coverage and run the project's existing tests. Work only in this repository; do not use network access or retrieve an upstream solution.
